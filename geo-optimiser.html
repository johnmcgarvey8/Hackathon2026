    How is the score calculated?

    Score = 100 × answers citing the exact submitted page / completed query-agent answers, rounded to a whole number. Each answer counts once. The profile filter changes the denominator. Brand mentions, other pages on the same domain, key-claim matches and Web IQ search positions are separate signals, not score boosts. A live run would exclude failed calls and report coverage; this fixture has no failures. This is a proposed metric, not an industry standard.

    02 / The workflow

    Eight stages. One governed loop.

    The GEO front-end agent moves from evaluation to drafting, human approval, CMS publishing and measured retesting.

    1. 01

      Fetch the page

      The marketer briefs the GEO agent with a URL and goal. The agent calls Microsoft Web IQ Browse for page content and metadata.

      Agent brief → snapshot

    2. 02

      Find target queries

      A query-generation LLM infers subject, audience and intent. The front-end agent presents candidate queries for marketer approval.

      Content → approved intent set

    3. 03

      Test visibility

      Run approved queries through Web IQ Search and Foundry agents with representative assistant-style profiles.

      Queries → answers + sources

    4. 04

      Measure presence

      Match the page, domain, brand and key claims in answers and citations. Score each query-agent result.

      Evidence → visibility matrix

    5. 05

      Compare sources

      When the page is missing, inspect cited competitors for relevance, authority, structure, clarity, factual support, freshness, citations and machine readability.

      Competing pages → gaps

    6. 06

      Package improvements

      Produce a Markdown task per recommendation and a manifest. Include evidence, edits, rationale and acceptance checks for downstream agents.

      Gaps → .md tasks + manifest

    7. 07

      Review & approve

      Ground the draft in authorised Work IQ context, validate claims and bind human approval to the exact content revision and CMS destination.

      Draft → approved revision

    8. 08

      Publish & maintain

      Publish the approved revision through a scoped Shopify or Sitecore connector, then monitor the live page and propose future FAQ updates.

      CMS receipt → retest loop

    03 / System architecture

    Evidence in. Approved content live.

    The front-end agent coordinates evaluation and drafting. Human approval and the CMS publishing service remain separate control boundaries.

    Real integration targets*

    Microsoft Web IQ, Work IQ, Foundry Agent Service, Shopify and Sitecore are real services. None is connected here; access, contracts and customer permissions must be confirmed.

    Proposed implementation

    The GEO front-end agent, evaluation orchestration, downstream editor/reviewer agents and connector-neutral publishing service need live implementation. Work IQ provides authorised guardrails; CMS adapters preserve customer workflow and least-privilege controls.

    Simulated in this file

    The conversation, scores, query results and recommendations are fictional. Brief approval, evidence filters, five downloadable Markdown files and a human-approval-to-CMS interaction work locally. No network request or real publication occurs.

    04 / Governed CMS publishing

    Publish designed in, approval kept separate.

    The target flow is signal to content to human approval to page update, with an audit trail. Shopify and Sitecore are illustrative destinations from the reference deck.

    Human approval boundary

    The agent prepares a CMS draft and preview. A person approves the immutable content revision, destination and release note. Any edit invalidates that approval.

    Nothing goes live without sign-off

    Customer CMS workflow

    A connector maps approved content into allowlisted Shopify PDP or collection fields, or Sitecore landing and campaign components. It preserves existing workflow states, concurrency checks and rollback evidence.

    Shopify and Sitecore are examples, not verified connectors

    Maintained FAQs with Work IQ

    Visibility gaps and changed authorised guidance can trigger an FAQ proposal. Work IQ supplies permission-trimmed brand voice, approved messaging and workflow context; a human still approves every publication.

    Continuously monitored, never unreviewed

    The proposed differentiators

    Measurement that leads to edits.

    01

    Retrieval and citation, side by side

    A page can appear in search without being cited. Separate the two to locate where visibility drops.

    02

    Competitor evidence behind the advice

    Compare passages selected by agents, rather than returning a generic SEO checklist. Treat explanations of selection as hypotheses.

    03

    Portable tasks for agent workflows

    Versioned Markdown carries evidence and acceptance checks into downstream drafting and review. Keep the baseline and query set for retesting, without promising an unverified uplift.

    06 / Technical approach

    Make the evaluation inspectable.

    Use deterministic matching where possible; use LLM judgement where interpretation is necessary.

    Agent-led orchestration

    The GEO front-end agent captures the brief and requests backend URL validation, Browse extraction and query-generation tools. The marketer approves intent before evaluation; service credentials remain server-side.

    Fan out the same queries to Search and three Foundry evaluator profiles. Pin locale, prompts, model versions and retrieval settings. The agent presents evidence, coverage, latency and cost through the dashboard.

    Match & compare

    Normalise URLs using declared canonical and redirect evidence. Keep exact-page citations separate from domain citations and brand mentions. Use a reviewed semantic check for key claims.

    Store raw answers and cited passages. Compare each missing-page result against the sources actually used, using the eight-factor content rubric from the workflow.

    Draft, approve & publish contract

    Render recommendations and .md files from shared structured data. Version the schema; preserve run/task IDs, evidence references, priorities, draft edits and acceptance checks in one manifest and individual tasks.

    Downstream agents prepare drafts with authorised Work IQ context. A separate CMS service verifies content and publish approvals against the exact revision, writes through a scoped connector, records the receipt and triggers a matched retest.

    07 / Hackathon scope

    Prove the governed loop.

    An agent-led brief, approved queries, dashboard evidence, Markdown tasks and a simulated human-approved CMS transition. Live downstream processing remains proposed.

    Hackathon MVP Planned

    • Brief a GEO agent and fetch one accessible page through Web IQ Browse.
    • Generate and review 5–10 high-intent queries.
    • Run Web IQ Search and up to three configured Foundry profiles.
    • Show exact-page citations, mentions, coverage and competing sources.
    • Deliver four evidence-linked draft recommendations, including an explicitly unverified technical check, and one proposed rewrite.
    • Export a Markdown manifest and four task files; validate their contract before any downstream integration.
    • Demonstrate a separate human approval and simulated Shopify/Sitecore publish action, with no external CMS call.

    Access fallback: use clearly labelled recorded fixtures if integrations are unavailable. No crawling behind logins, direct consumer-assistant testing, unapproved publishing or guaranteed ranking improvement in the MVP.

    Future roadmap

    1. Next / Connect and validate agents

      Implement the live GEO front end and evaluate downstream consumers against the Markdown contract. Add Work IQ-grounded drafts and human review.

    2. Then / Publish to one CMS sandbox

      Implement either a Shopify or Sitecore adapter with allowlisted destinations, immutable approvals, audit receipts, conflict detection and rollback.

    3. Later / Maintained content workflows

      Monitor enrolled FAQ blocks, propose bounded updates from Web IQ and authorised Work IQ context, publish only after approval and retest the exact revision.

    4. Longer term / Business outcomes

      Connect observed citations with referral analytics and conversions where attribution is available. Test whether the workflow changes marketing decisions.

    08 / Risks & guardrails

    Be precise about what we know.

    Visibility is observable. The reasons an external system selects a source are only partly observable.

    RiskDesign response
    Profiles are imperfect proxiesCopilot, ChatGPT and Claude have proprietary retrieval, prompts and personalisation. Label Foundry results as profile tests; never claim consumer-product parity.
    Access, cost & retrieval gapsConfirm Web IQ access and model availability early. Cap queries and retries; disclose extraction failures, unavailable pages and incomplete agent runs.
    Correlation mistaken for causationSource comparisons suggest hypotheses, not ranking factors. Preserve baselines, repeat runs and use held-out prompts; do not promise citation uplift.
    Untrusted content & unsafe URLsBlock private, local and metadata addresses, revalidate redirects and DNS, restrict egress and page size, and treat fetched text as untrusted data. Keep secrets server-side and never execute page instructions.
    Fabricated evidence or content misuseRequire traceable sources and human review. Respect access restrictions, site terms, privacy and copyright. Do not bypass paywalls or copy competitors' passages into proposed content.
    Unsafe or stale agent hand-offsValidate schema versions, run/task IDs, evidence and file references. Treat brief and retrieved text as untrusted data, not instructions. Draft-only metadata is not a security boundary: downstream runtimes must independently restrict tools and require human approval before publication.
    CMS overreach or stale approvalUse a dedicated least-privilege identity, allowlisted destinations, immutable revision hashes, concurrency checks, idempotency and a publication receipt. Reject changed, expired or unapproved drafts; retain a rollback or compensating-change path.
    Work IQ context is stale or conflictingUse permission-trimmed retrieval from designated authoritative sources, record freshness and provenance, surface conflicts and require a human to resolve them. Never treat retrieved content as approval.
    09 / Success metrics

    Earn trust before claiming impact.

    Proposed evaluation criteria, not achieved results. Set numeric targets after establishing a baseline.

    Measurement accuracy

    Citation and mention precision/recall against a human-labelled sample. Inspect canonical-URL and brand ambiguity errors.

    Judge: can we trust the evidence?

    Editorial & hand-off quality

    Recommendation usefulness, Markdown contract validity and downstream comprehension of evidence and acceptance checks. Measure time to an approved draft.

    Judge: can the next agent use it?

    Visibility change

    Change in exact-page citation rate over repeated before/after runs. Report sample size, coverage and uncertainty.

    Judge: does the change hold up?

    Operational viability

    Completed evaluation and publication rates, end-to-end latency, cost per page, approval trace completeness, connector conflicts and rollback outcomes.

    Judge: can we run it responsibly?
